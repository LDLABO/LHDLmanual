図5.8 キーの短絡
    　　　 

図5.8 はキーボードの一部を抜粋したものです、これで 0 と = のキーを同時 に押すと B0 と B1 につながれたIC の出力は短絡してしまいます。 1 と 2 のキーでも同じことが起こります。 0 と 1 または = と 2 のキーを同時に押しても 短絡は起こりません。短絡を防ぐためにはダイオードの代わりに抵抗を使うこ ともできます。これでも壊れることは防げますが複数のキーが押されたときに 正しく読み取れなくなる場合があります。


　　キーボードの論理

4 行4 列のキーボードを駆動する論理を作ります。 チップの概観は 図5.9 のようになります。

　　　チップ概観
図5.9 チップ概観
    　　　 
  • RESET : チップを初期化します。
  • SCLK : キーボードを駆動するCLK で1CLK で1 列を駆動して、それにつながる1 行のキーを 読み取ります。
  • Q[4] : キーボードで押されたキーのデータです。上の2 ビットに列のデータがあります。下の2 ビットに行 のデータがあります。
  • SET : キーボードでキーが押されていてQ[4] にデータがあることを示します。
  • TAKE : Q[4] のデータを読み取った後に本端子を1 にしてSET を解除させます。
  • YIN[4] : キーボードの行を読み取る端子です。
  • XSEL[4] : キーボードの列を駆動する端子です。

　　　キーボードの駆動と読み取り
図5.10 キーボードの駆動と読み取り
    　　　 

Q[4] のデータは新たなキー入力があっても TAKE を 1 にして SET が解除しないと更新されません。 Q[4] のデータの構成は 図5.10 のようになっています。行と列がそれぞれ2 ビットなので、ひとつのキーだけが押され たことしかデータにしていません。複数の列でキーが押 されても駆動されている列につながっている行のスイッ チだけが認識されるような回路であることを前提にして います。同一の列の中の複数の行でスイッチが押された ときは優先順位をつけてひとつのキーだけをデータにす るように論理を作ります。
