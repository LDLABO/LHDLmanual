　　端末の実行
　　　キー入力

端末の検証はキーボードを擬似的に押すことで進めていきます。端末の論理が引用しているキーボードの論理 では同時にふたつのキーが押されることはなくキーが離されてから次のキーが押されるような操作を前提にして います。


図5.65　キーの1 を押したところ
    　　　 
図5.66　キーの1 を離したことを確認したところ
    　　　 

図5.65 の XSEL が 1 で YIN が 2 になっているところはキーの 1 を押したところで OFF が 1 から 0 になっています。キーボードはこの後に全列を駆動して全列の YIN が 0 になっていることを確認してキーが離されたと 図5.66 のように認識して OFF が 0 から 1 になっています。キーの 1 が離されたときにキーを押した回数の tp をひとつ増やします。

　　　メモリの読み出し

端末の実行では次の3 箇所でメモリを外から読み出しています。

  • 検証手順の 図5.64 の ① が終わった後にメモリの値を 図5.67 のように読み出します。 リスト138 の tp が 7 のところでキーの 8 が押された後がその位置です。
  • 検証手順の 図5.64 の ③ が終わった後にメモリの値を 図5.68 のように読み出します。 リスト138 の tp が 10 のところでキーの 0 が押された後がその位置です。
  • 検証手順の 図5.64 の ④ が終わった後にメモリの値を 図5.69 のように読み出します。 リスト138 の tp が 11 のところでキーの = が押された後がその位置です。
