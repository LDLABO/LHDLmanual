　　論理設計とプログラミング

言語で論理設計したもをプログラムと呼ぶ人もあるようですからマイコンのプログラム言語と論理設計の言語 の相違を見てみたいと思います。左がマイコンのプログラムで右が同様の機能を持つ論理設計の言語表記です。 


entity main
input  RESET;
output ADDRESS[4];
output DATA[8];
output WE;

bitr i[4];
bitr memseq[3];
bitn we;

   ADDRESS=i;
   DATA=0xff;
   WE=we;

   if (RESET)
      i=0;
   else
      if (i<5)
         switch(memseq)
            case 4:  i=i+1;
            default: i=i;
         endswitch
      else
         i=i;
      endif
   endif

   if (RESET)
      memseq=0;
   else
      switch(i)
         case 5: memseq=memseq;
         default:
            switch(memseq)
               case 4: memseq=0;
               default: memseq=memseq+1;
            endswitch
      endswitch
   endif

   switch(memseq)
      case 1:
      case 2:
      case 3:
      from: we=1;
   endswitch

ende
　　　プログラミング

main()
{
int i,a[5];

   for(i=0; i<5; i++)
      {
      a[i]=0xff;
      }
}

マイコンのプログラムのデータ操作はほぼメモリに対す るものです。しかしこれがマイコンのコードにコンパイ ルされた実行プログラムではマイコンの内部のレジスタ も操作しているはずです。他のメモリを操作したり他の プログラムを呼び出しているかも知れません。これらの 動きはコンパイラによって行われていますがアセンブ リ言語でプログラムを書く人はこれを自分で書いてい ます。 


       .8086
        CODE segment

        MOV   BX,0
        MOV   AX,0FFH
ROOP:
        MOV   DS:[BX],AX
        INC   BX
        CMP   BX,5
        JC    ROOP

        HLT
        CODE ends
        end

同じマイコンのプログラムとは言っても高級言語でプロ グラム作る人とアセンブリ言語でプログラムを作る人の 意識は大きく異なると思います。高級言語はマイコンの 種類は問いませんデータ操作についてどのメモリで行う のかを指定する必要もありません。アセンブリ言語はメ モリの種類は問いませんどのような種類であってもマイ コンで読み書きできるように作られている前提があり ます。 高級言語でもアセンブリ言語でも感知できないかあるいは感知する必要のない前提を持っています。
