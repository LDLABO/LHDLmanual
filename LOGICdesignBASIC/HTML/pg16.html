　　　時分割で書いた場合
リスト4　8 ビットの加算器no.3
 　　  

entity main
input  RESET;
input  A[8];
input  B[8];
input  C[8];
input  D[8];
output E[8];
output F[8];

bitr sel;
bitr e[8];
bitr f[8];
bitn seldataa[8];
bitn seldatab[8];
bitn add[8];

   E=e;
   F=f;

   if (RESET)               { 選択計数器 }
      sel=0;
   else
      sel=sel+1;
   endif

   if (sel)
      seldataa=D;           { 入力選択f }
   else
      seldataa=A;        　 { 入力選択e }
   endif

   if (sel)
      seldatab=C;           { 入力選択f }
   else
      seldatab=B;           { 入力選択e }
   endif

   if (RESET)               { 記憶 e }
      e=0;
   else
      if (sel)
         e=e;
      else
         e=add;
      endif
   endif

   if (RESET)               { 記憶f }
      f=0;
   else
      if (sel)
         f=add;
      else
         f=f;
      endif
   endif

   add=seldataa+seldatab;   { 加算器 }

ende

次の式を1 個の加算器で行うために時分割の論理 を リスト4 に書いてみました。 


E=A+B
F=C+D

実行の結果は 図3.2 のように E と F の結果が出てくるのには時間差があります。

図3.2 8 ビットの加算器no.3

sel はチップのCLKで計数されており 0 1 0 1 0 ・・・ と動いています。 sel が0のときに E の計算を行い sel が1のときに F の計算を行っています。 E と F の計算は時分割で行われているので結果は e と f に記憶しています。

論理設計の工夫はどちらかと言うと速度を上げるこ とよりも論理を小さくする方に向けられる事が多いと 思います。CPLD に入れるつもりで設計を始めても ギリギリで入らないなどはよくあることですので論 理を減らして時分割で行うなどは今のCPLD の容量 ならまだまだあり得る話です。今回は加算器でしたが もっと大きな論理を時分割で利用する場合は効果が大 きいです。

加算器を他の演算器に変えても同様の事が行えま す。演算器を多機能に変えて算術演算ユニットALU にして、その機能の選択を固定ぜずプログラムで変え ていけばマイクロプロセッサになります。
