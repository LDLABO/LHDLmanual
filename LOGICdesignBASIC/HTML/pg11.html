　　　PLD と記憶

PLD の記憶はレジスタや計数器やシフトレジスタなど色々とある訳ですが同期式では 図2.7 のようになります。チップの初期化時に記憶値を0 にしたいときはふたつの論理積が0 になるようにします1 に したいときは論理和が1 になるようにします。

図2.7 PLD と記憶

図2.7 の構造は 図2.5 によって作ることができま す。同期式の順序論理はC に作られる記憶信号の 論理やデータの論理の違いがあるだけで基本の構 造は 図2.7 と同じです。 図2.7 は記憶信号をSEL、 データをDATA、出力をQ とすると論理式は 

          Q = Q*!SEL + DATA * SEL

になります。同期式によるPLD の論理は真理値 表と記憶素子によって駆動されることを念頭におい て設計します。



　　　PLD と言語

真理値表から論理式、論理式から文構造を持つ書き方に移行して来ていますが同期式では記憶の方法をひとつ だけにしているので非常に簡潔に書き表せます。 

Q = Q*!SEL + DATA * SEL
       は        

if (SEL)
   Q=DATA;
else
   Q=Q;
endif
       になります。

　　　設計しやすくなった

加算器も　 c=a+b; のように書けます加算器がどのような真理値表になるかは前に書いた通りです。文で書 くよいところは論理構造が分かりやすくなったことがあると思います。これでかなり細かく書いていくことがで きますし保守性もよくなりました。


　　　言語で書いても大きくならない

マイコンのプログラムはC 言語で書いたものはアセンブリ言語で書いたものより動きが遅くなることがある ようですが論理設計を言語で書いた場合は最終的に真理値表になり、それには論理圧縮などの確立された最適化 の方法があるので他の方法で設計した場合に比べて著しい差が出てくるとは思えません。論理設計の言語表記は 書きやすくてチップにするときにも論理の効率を落とす心配もありません。


　　　似て非なるもの

マイコンのプログラミングの言語と論理設計の言語は前提にしているものが違うので同じような言語で書いて いてもマイコンとPLD の言語設計は同じではありませんマイコンの場合はコードの列を作っているのであり論 理設計の場合は真理値表を作っています。最終的には 図2.5 の構造によって実現されると頭に描いていれば明瞭 な論理設計が行えると思います。
