  • SUB rx,r3
    rx から r3 を減算します rx は r4 か r5 になります結果は rx に記憶します。
  • SLA r3,n
    r3 を上位方向に n ビットずらして r3 に記憶します n は即値で1 から8 です。
　リスト65　マクロ追加部分
 　  

;       DIV r0,n
macro     DIV R,NUMBER
   db 23,#0,#1&0ffh,0
endm
;       SUB r0,n
macro     SUB R,NUMBER
   db 25,#0,#1&0ffh,0
endm
;       SLA r0,n
macro     SLA R,NUMBER
   db 27,#0,#1&0ffh,0
endm
;       CP r0,n
macro     CP R,NUMBER
   db 19,#0,#1&0ffh,0
endm
 　 

今回追加した命令を PPU.MAC に リスト65 のように書き加えます。実際には 「LED の点灯の移動」で使ったプロセッサには CP 命令と SLA 命令を使っていましたので追加するのは残りの DIV 命令と SUB 命令です。 DIV 命令と SUB 命令の書式は同じで #0 はレジスタ枠0 で示すレジスタの番号を NUMBER は8 ビットの即値を示します。


　　　論理

論理を部分的に抜粋して説明しますので全部は BCDPPU.pdf を参照して下さい。プロセッサの基本部分と追加部分との構成は 図4.21 のようになっています、構成要素は次のものがあります。

  • プロセッサ基本部分
  • レジスタ
  • フラグ
  • 演算器
  • 除算器
  • プログラム
図4.21 全体構成
    　　　 

除算器は記憶型なので非記憶型 の演算器とは別にしています。本 論理の各構成要素の中身はBCD 変換器に特化したものですが全体 構成はどのような場合もほぼこれ と同じ構成になると思います。プ ログラムがあることでどのような 場合にも構成を大きく変えないで あらゆる機能に対応できることが分かります。除算器を省略したりとかレジスタの数を減らしたりとかは実行時 間は長くなりますが機能をプログラムに負担させることでできます。論理設計でする方がいいのかプログラミン グでする方がいいのかという問題は基本的には論理設計でする方がいいと思いますが専用のメモリチップを外に 置ける場合は大きなプログラムを動かせるのでそれが有利な場合もあると思います。
