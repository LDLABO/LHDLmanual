　　　アセンブラ

独自のプロセッサをアセンブリ言語でプログラミングするためにマクロアセンブラのマクロ機能を使ってアセ ンブラを作ります。マクロアセンブラは http://www9.plala.or.jp/sagae_/ の Electric House で開発された AASM を使わせて頂きました。 AASM は独自のプロセッサを作るときのプログラミング環境の問題の解決と言 う点で論理設計者の大きな助けになります。開発元サイトでは 「AASM は汎用マクロアセンブラで、マクロ定 義によって様々なCPU に対応可能です。Version3.50 からＣ言語ライクなマクロも定義できるようになりまし た。」 のように紹介されています。

本プロセッサ用に作ったマクロを部分的に抜粋して説明します。全部は PPU_MAC.pdf を参照して下さい。

図4.6 LD r0,r1
    　　　 
　リスト42　LD r0,r1 マクロ
 　  

1: macro     LD R,R
2:    db 03,#0,#1,0
3: endm
 　 

● LD r0,r1

リスト42 は 図4.6 をマクロに書いたものです。

  • 行番号1 の1 番目の R はレジスタ枠0 を示します。
  • 行番号1 の2 番目の R はレジスタ枠1 を示します。
  • 行番号2 の #0 がレジスタ枠0 で選択されたレジスタの番号を示します。
  • 行番号2 の #1 がレジスタ枠1 で選択されたレジスタの番号を示します。

マクロで使うレジスタの定義は const R = R0,R1,R2,R3,R4,R5,R6,R7 なので R0〜R7 は0〜7 になります。 LD R2,R3 のアセンブラの解釈は db 3,2,3,0 になります。 db はアセンブリ言語で8 ビットのデータを定義す る命令です。


● NOP

 　  

macro     NOP
   db 00,00,00,00
endm
 　 

レジスタ枠はひとつも使っていません。


● JP n'n

 　  

macro     JP NUMBER
   db 01,(#0>>10)&0ffh,(#0>>2)&0ffh,0
endm
 　 

#0>>10 は NUMBER を下位に10 ビットずらすという意味です。アセンブラの解釈は db 1,n',n,0 になります n' は4 バイト番地の上位8 ビットです。本プロセッサは4 バイトでひとつの番地ですから4 バイト番地はバイト単 位の番地の1/4 になります。ですから NUMBER から上位8 ビットの4 バイト番地を取り出すためには下位に8 ビットずらして、さらに2 ビットずらした値が実際の4 バイト番地の上位8 ビットです。 n は4 バイト番地の下位8 ビットです、同じく下位に2 ビットずらして4 バイト番地の下位8 ビットになります。


● JZ n'n

 　  

macro     JZ NUMBER
   db 02,(#0>>10)&0ffh,(#0>>2)&0ffh,0
endm
 　 

定義の内容は JP n'n とほぼ同じです。
